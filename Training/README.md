# 랭크 배틀 AI 학습 (1단계: 환경 + 기준선)

림월드 없이 **엔진만** 돌려서 학습한다(엔진은 순수 C#). 학습 대상은 "플레이어 쪽" 정책이고, 상대는 기존 AI/랭크 AI/무작위다.

## 준비 (Windows)
1. .NET 8 SDK 설치 (`dotnet --version` 이 8.x)
2. Python 3.10~3.12, 그다음 `pip install -r Training/python/requirements.txt`
   (GPU를 쓰려면 pytorch 공식 사이트의 CUDA 빌드로 torch 설치. MLP는 CPU로도 충분히 빠르다)
3. 환경 빌드: `dotnet build -c Release Training/TrainEnv`

## 실행 (Training/python 폴더에서)
- 환경 점검(torch 불필요): `python smoke_test.py` — 무작위 에이전트로 몇 판 돌려 속도·승률을 본다. 이 샌드박스에서 프로세스 1개당 약 1300~3300 step/s.
- 학습: `python train.py --steps 3000000 --envs 10` (i5-12400이면 envs 10 권장). 20만 step마다 랭크AI/기존AI/무작위 상대 승률을 출력하고 `runs/ppo1/best`, `latest`를 저장한다.
- 평가: `python eval.py runs/ppo1/best --games 300`
- 모드용 내보내기: `python export_weights.py runs/ppo1/best policy.bin`

## 구성
- `Engine/Battle/AiEncoder.cs`: 관측 1377차원(내 3마리 + 상대 3마리 + 필드). 종족 이름 대신 능력치·타입·기술 특성만 쓴다 → 처음 보는 ?티어도 같은 방식. 상대의 안 나온 림켓몬/안 쓴 기술은 가린다. 행동 6개(기술 4 + 교체 2), 불법 행동은 마스크.
- `Engine/Battle/NeuralPolicy.cs`: 내보낸 가중치를 읽어 추론(순수 C#, 외부 라이브러리 없음). `Choose(..., temperature)`로 확률적 선택(0이면 최고 점수 하나만) → 읽히기 어렵게 섞어 쓸 수 있다.
- `Training/TrainEnv`: 표준입출력 이진 프로토콜의 헤드리스 환경. 선출은 지금은 규칙 기반으로 고른다.
- 보상: 승 +1 / 패 -1, `--shape`로 쓰러뜨림/쓰러짐 중간 보상(기본 0.1).

## 아직 안 한 것 (다음 단계)
1. **상대 시점 인코더**: 모드에서 학습된 정책을 랭크 상대 AI로 쓰려면 "상대(foe) 입장" 관측/합법 행동을 만들어야 한다(지금은 플레이어 시점만).
2. **자기 대전(self-play)**: 지금은 고정된 AI 상대. 상대도 정책으로 두고 서로 학습시키면 더 강해진다(상대 쪽 외부 행동 주입 훅 필요).
3. **특성·도구 입력**: 지금 관측에는 특성/도구가 빠져 있다(종류가 많아 임베딩이 필요).
4. 선출(6마리 중 3마리 고르기)과 더블 배틀은 학습 대상이 아니다.
5. 확률적 정책 + 얕은 탐색을 합치는 하이브리드.

## 자기학습 (3단계)
2단계(runs/ppo3) 결과가 500판 기준 랭크AI 상대 약 54%에서 멈춰서, 상대도 신경망이 조종하는 자기학습으로 넘어간다.

- 실행(Training/python 폴더): `py -3.10 train.py --selfplay --resume runs/ppo3/final --out runs/sp1 --steps 20000000 --envs 20 --device cuda`
- 상대 구성: 판의 70%는 과거 시점의 내 정책(절반은 가장 최근 것, 절반은 최근 10개 중 아무거나), 30%는 랭크 AI/기존 AI(기존 실력을 잃지 않게).
- 50만 step마다 현재 정책을 `runs/sp1/pool/opp_*.bin`으로 내보낸다(최근 10개만 유지). 환경(C#)이 이 파일을 읽어 상대(Foe)를 조종한다.
- 구현: `AiEncoder(settings, asFoe: true)`가 Foe 입장의 관측·마스크·행동을 만든다. 자기학습 판은 온라인 대전용 엔진 경로(`OnlineBattle`/`OnlineAct`)로 양쪽 행동을 동시에 넣는다. 상대 정책은 확률대로 뽑는다(temperature 1).
- 평가 변경: 100만 step마다, 랭크AI 300판(+기존AI·무작위 100판씩), **매번 다른 판**으로 잰다. 예전에는 같은 100판을 반복해서 재서 중간 평가(62%)가 실제(54%)보다 높게 나왔다.
- 이어서 학습할 때 학습률은 1e-4에서 시작해 1e-5까지 줄어든다(`--lr`로 변경 가능).
- 학습 속도 개선: 환경 N개를 C# 프로세스 하나가 스레드로 동시에 돌리고 파이썬과는 걸음마다 한 번만 주고받는다(`BatchVecEnv`, 기본값). 예전 방식은 `--subproc`. 2코어 샌드박스에서 학습 fps 약 350 → 1080. 이를 위해 엔진의 전투 간 공유 상태(화학변화가스·매직룸 조회기)를 전투별로 분리하고 능력치 함수 캐시에 잠금을 넣었다.
- 학습 속도 점검 결과: 자기학습 한 걸음에서 상대 신경망 추론이 C# 시간의 절반 이상이었다. 가중치를 입력 기준으로 뒤집어 0이 아닌 입력만 연속 메모리로 더하도록 바꿈(학습 환경 빌드는 SIMD 사용) → 추론 0.24ms → 0.07ms, 자기학습 환경 속도 약 1.6배. 관측은 공유 메모리로 전달. `train.py --profile N`으로 파이썬 쪽 시간 분석 가능.

## 선출 학습 (4단계)
- 판이 시작되면 먼저 **선출 3걸음**: 내 6마리 중 한 마리씩 고른다(행동 0~5 = 6마리 중 하나, 첫 번째가 선봉). 전투와 같은 6칸 행동을 같이 쓴다. 종족·도구 중복은 마스크로 막는다.
- 관측이 7222칸으로 늘었다: 전투 부분 3501 + 프리뷰 3721(선출 단계 표시 1, 내 6마리 전체 정보 + 골랐는지/순서, 상대 6마리의 타입·최대HP만). 프리뷰는 전투 중에도 남는다(상대가 데려왔을 수 있는 후보를 안다).
- 상대의 선출: 랭크AI/기존AI 상대는 기존 규칙(PickForFoe), 자기학습 상대는 상대 정책이 직접 고른다.
- 예전 모델 이어받기: `--widen runs/sp1/final`. 새 입력 자리의 가중치는 0에서 시작하므로 전투 실력은 그대로이고 선출만 새로 배운다. 예전 정책 파일(3501칸)은 상대 풀에서 쓸 수 없으니 `--out`은 새 폴더로.
- 실행: `py -3.10 train.py --selfplay --widen runs/sp1/final --out runs/pick1 --steps 30000000 --envs 256 --n-steps 128 --device cuda`
- 주의: 이제 평가도 "AI가 직접 선출"한 결과다. 처음에는 선출이 무작위에 가까워서 예전 숫자(규칙 선출)보다 낮게 시작할 수 있다.

## 팀 구성 통계
학습을 돌리면 `runs/<이름>/team_meta.txt`가 자동으로 생긴다(어떤 종족·도구·특성·기술을 데려간 쪽이 이겼는지). 모드에 쓰려면 이 파일을 `Rimketmon/Rimketmon/Data/team_meta.txt`로 복사한다. 자세한 규칙은 상위 README의 "팀 구성 학습" 참고.

### AI 학습: 왜 랭크AI 상대로 52%에서 멈추는가 (점검 결과)
- 선출 학습 30M step 결과: 랭크AI 52% / 기존AI 55% / 무작위 85%. 선출은 규칙 수준까지 배웠지만(무작위 상대 75% → 85%) 랭크AI 상대는 그대로.
- 점검 실험(규칙 선출, 랭크AI 상대 300판): 무작위로 두면 9%, 첫 번째 기술만 누르면 19%, **이번 턴의 난수와 상대 행동까지 미리 보고 가장 이득인 수를 고르는 반칙 에이전트도 34%**. 학습 모델은 52%.
- 원인: 랭크AI는 내 림켓몬의 정확한 능력치·특성·기술 전부를 보고 판단한다(피해 계산, 선출, 교체). 학습 모델은 화면에 보이는 것만 본다(상대 능력치·도구 숨김, 기술은 쓴 것만). 즉 정보가 불리한 쪽이 비긴 것이라 "60% 기준"이 애초에 불공평했다.
- 대응: `--full-info`(환경 변수 RIMKET_FULLINFO=1)로 상대 정보를 전부 보는 모델을 학습할 수 있게 함 → 랭크AI와 같은 조건. 관측 크기는 같아서 지금 모델에서 이어 학습할 수 있다. 평가에도 같은 옵션을 붙여야 한다. `eval.py --rule-pick`은 선출만 규칙에 맡겨 잰다.

## 2026-11-12 — 학습 단계 속도 개선(빠른 버퍼), 시간 배분 3분할
- `FastBuffer`: 한 번 모은 데이터(관측 등)를 학습 장치(GPU)에 통째로 올려 두고 묶음을 거기서 뽑는다. 이전에는 묶음마다 CPU에서 골라 GPU로 보냈다(256환경×128걸음이면 한 번에 128회, 회당 약 30MB). 학습 결과는 같다. GPU 메모리가 모자라면 자동으로 예전 방식, `--slow-buffer`로 끌 수 있다.
- `[시간 배분]`이 환경(C#) / 행동 고르기(신경망) / 학습 세 부분으로 나온다.
- GPU에서의 실제 속도 향상은 측정하지 못했다(작업 환경에 GPU 없음, CPU에서는 차이 없음이 정상).
