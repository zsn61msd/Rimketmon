# PokeRogue 배틀 영상 분석 (림켓몬 UI 재제작용)

분석 대상: Pok_Rogue_2026-11-10_16-28-13.mp4 (2560×1372, 29.97fps, 63.1초, 1,840프레임 전부 추출).

## 1. 화면 규격 (측정)
- 게임 영역: 가로 2440px (좌우 60px 어두운 바), 세로 1372px → 원본 320×180 유닛 기준 **7.62px/유닛**.
- 그래서 영상 좌표는 `px ÷ 7.62 = 게임 유닛`으로 환산해 PokeRogue 소스 값과 비교한다.

## 2. 영상의 게임 속도 — 실측 약 3배속 vs 사용자 증언 1배속 (미해결)
> 사용자는 '포켓로그 1배속으로 녹화'라고 했으나 프레임 간격 실측은 소스의 1배속 ms 값보다 약 3배 빠르다. 구현은 소스의 1배속 ms 값을 기준으로 하고 모드 설정의 게임 속도(기본 1.0배)로 나눈다. 더 빠르게 원하면 설정에서 올리면 된다.
| 지표 | 소스(1배속) | 영상 측정 | 배율 |
|---|---|---|---|
| 볼 x 이동 (36→100) | 650ms | 프레임당 10.3유닛 = 약 0.31유닛/ms (n520~525) | 약 3.1배 |
| 볼 y 정점(80→70) | 150ms | 1프레임 | 약 3배 |
| 볼 낙하(→132) | 500ms | 약 5프레임(167ms) | 약 3배 |
| 메시지 출력 | 글자당 20ms (16자=320ms) | 약 3프레임(100ms) | 약 3배 |
| 적 정보창 슬라이드 | 1000ms (Cubic.easeOut, 150유닛) | 약 12프레임(400ms) | 약 2.5배(이징 영향) |
→ **영상은 게임 속도 3배로 녹화된 것.** 림켓몬은 소스의 1배속 값을 기준값으로 저장하고, 설정의 게임 속도(1~5배)로 나눈다. (기본 1배)

## 4. 소스에서 확정한 수치 (1배속, ms)
- 플레이어 트레이너 퇴장: x → -36, 1000ms. 볼 발사는 750ms 뒤.
- 볼: 아군 출발 (36,80)→(100+offset, …) / 적 출발 (248,44)→(236+offset,…). 도착 y 아군 132, 적 86.
- 등장 후 1000ms 대기 뒤 다음 단계.
- 정보창: 등장 1000ms Cubic.easeOut(아군 +150→0, 적 -150→0), 퇴장 500ms Cubic.easeIn.
- HP바: 시간 = clamp(|ΔHP|×5, 250, 5000)ms, Sine.easeOut (설정 hpBarSpeed로 단축).
- 메시지: 글자당 20ms 기본. 기본 정보창 위치: 아군 (캔버스폭-10, -72), 적 (140, -141) (컨테이너 기준).

## 5. 구현 원칙
1. 모든 연출 시간은 위 1배속 ms 값 그대로 상수로 두고 `÷ gameSpeed`로 재생한다.
2. 이징은 Sine/Cubic을 수식으로 구현한다.
3. 배경은 PokeRogue 바이옴 아레나 이미지를 림월드 바이옴에 매핑해서 쓴다.
4. 포켓몬 스프라이트는 PokeRogue 앞/뒤 스프라이트를 그대로 쓴다.

## 6. 아직 분석/확보하지 못한 것 (정직하게)
- UI 패널 이미지(images/ui)와 트레이너 스프라이트(images/trainer)는 올려주신 압축이 잘려서 없다. 파일 없이는 패널/트레이너 외형을 원본과 동일하게 만들 수 없다.
- 영상 후반 구간(기술 사용, 쓰러짐, 경험치, 보상 화면)의 세부 프레임 타이밍은 아직 측정하지 않았다. 커맨드/기술/가방/파티 화면의 정확한 좌표도 소스 대조 전이다.
